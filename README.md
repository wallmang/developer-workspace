\# 개발자 작업실 구축 미션



\## 1. 프로젝트 개요

Docker를 이용해 웹 서버를 실행하고 브라우저에서 접속하는 개발 환경을 구축했다.



\## 2. 사용 환경

\- 운영체제: Windows

\- 버전 관리: Git

\- 컨테이너 실행 환경: Docker Desktop

\- 웹 서버: Nginx



\## 3. 프로젝트 구성

\- `Dockerfile`: 웹 서버 이미지 생성 설정

\- `app/index.html`: 웹 페이지 파일



\## 4. 실행 및 검증

1\. Docker 이미지를 `my-dev-web` 이름으로 빌드했다.

2\. `my-dev-container` 컨테이너를 실행했다.

3\. 포트 8081을 통해 웹 서버에 접속했다.

4\. 브라우저에서 직접 작성한 웹 페이지가 표시되는 것을 확인했다.



\## 5. 사용한 주요 명령어

```powershell

git --version

docker --version

docker images

docker ps -a

docker build -t my-dev-web .

docker run -d --name my-dev-container -p 8081:80 my-dev-web

```



\## 6. 트러블슈팅

\### 문제 1. Dockerfile 이름 오류

\- 문제: 파일이 `Dockerfile.txt`로 저장되어 있었다.

\- 원인: 파일 이름에 `.txt` 확장자가 추가되었다.

\- 해결: 파일 이름을 `Dockerfile`로 변경했다.



\### 문제 2. 웹 서버 접속 실패

\- 문제: `localhost:8081`에 접속할 수 없었다.

\- 확인: `docker ps -a`에서 새 컨테이너가 생성되지 않은 것을 확인했다.

\- 해결: Dockerfile을 확인하고 이미지를 빌드한 다음 컨테이너를 실행했다.



\## 7. 결과

Docker 이미지를 생성하고 컨테이너를 실행하여 웹 페이지 접속에 성공했다.

## 8. 절대 경로와 상대 경로

- 절대 경로는 드라이브나 루트부터 파일의 위치를 나타내는 전체 경로이다.
- 상대 경로는 현재 작업 위치를 기준으로 파일의 위치를 나타낸다.
- 예를 들어 `C:\Users\ymh20\developer-workspace\app\index.html`은 절대 경로이고, `app/index.html`은 `developer-workspace` 폴더를 기준으로 한 상대 경로이다.

## 9. 파일 권한

- `r`은 읽기, `w`는 쓰기, `x`는 실행 권한을 의미한다.
- `755`는 소유자에게 읽기·쓰기·실행 권한을 주고, 그룹과 다른 사용자에게 읽기·실행 권한을 준다.
- `644`는 소유자에게 읽기·쓰기 권한을 주고, 그룹과 다른 사용자에게 읽기 권한을 준다.

## 10. 포트 매핑

- 포트 매핑은 호스트 컴퓨터의 포트와 컨테이너 내부의 포트를 연결하는 것이다.
- 이번 실습에서는 `-p 8081:80`으로 호스트의 8081번 포트를 컨테이너의 80번 포트에 연결했다.
- 이를 통해 브라우저에서 `localhost:8081`로 웹 서버에 접속할 수 있었다.

## 11. Docker 볼륨

- Docker 볼륨은 컨테이너와 데이터를 분리하여 데이터를 유지할 수 있도록 한다.
- `my-dev-volume`을 만들고 `test.txt` 파일에 데이터를 저장한 뒤 다시 읽어 확인했다.
- 컨테이너가 삭제되더라도 볼륨 자체를 삭제하지 않으면 저장된 데이터를 유지할 수 있다.

## 12. Git과 GitHub

- Git은 파일의 변경 내역을 기록하고 관리하는 버전 관리 도구이다.
- GitHub는 Git으로 관리하는 프로젝트를 온라인에 저장하고 공유하는 플랫폼이다.
- 이번 실습에서는 Git으로 파일을 커밋하고 GitHub에 업로드했다.
